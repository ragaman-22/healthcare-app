## 2. 実行方法

```bash
cd tax-app
npm install
npm test            # 単体テスト
npm run typecheck   # 型チェック
npm run lint        # Lint
npm run build       # 本番ビルド
npm run test:db     # DB テスト（PostgreSQL 15 以上の initdb / pg_ctl / psql が必要）
```

`test:db` は使い捨ての PostgreSQL を起動し、Supabase の `auth` スキーマの最小限の代替（`supabase/tests/00_supabase_stub.sql`）を作ってから全マイグレーションを適用し、`supabase/tests/10_rls_and_books.test.sql・20_receipts.test.sql` を実行します。

### DB テストで確認していること

- 利用者 A の取引保存で仕訳が作られ、更新で作り直され、版数が上がり、履歴が残る
- 貸借不一致・片側だけの仕訳・存在しない科目は保存できない
- 標準科目、計算結果・履歴は利用者が変更・削除できない
- 利用者 B から A の取引・仕訳・明細・履歴・独自科目が見えない
- B が A の取引 ID で上書き・削除しようとするとエラー（A のデータは変わらない）
- `user_id` を偽装した INSERT、A の取引に紐づく仕訳の作成は拒否
- 未ログインでは保存できない
- 取引を削除すると仕訳も削除され、履歴が残る
- 証憑を経費に登録すると「登録済み」になり、別の取引には登録できず、削除もできない
- 他人の証憑・OCR 結果は見えず、自分の取引に紐づけることもできない
- 取引を削除すると証憑は「確認待ち」に戻り、削除できる（OCR 結果も削除される）
- 控除の詳細・給与収入は本人のみ参照・登録でき、不明な種類は登録できない
- 通知書・納付済みの記録は本人のみ。納付のキーの形式・重複を DB で拒否

## 3. 税金計算テストの方針

- 期待値は **手計算または公式資料の計算例** で求め、テストコードにコメントで根拠を残す。
- 端数処理（1,000円未満・100円未満・1円未満の切捨て）が効くケースを必ず含める。
- 税率・控除の **境界値** の前後をテストする（累進税率で税額が連続していること）。
- 未対応・情報不足の場合に「計算不可」や警告が出ることもテストする。
- 新しい年度のルールを追加したら、その年度のケースを追加する（前年度のテストは回帰テストとして残す）。

## 4. 照合が必要な検証（第4段階以降）

- 国税庁「確定申告書等作成コーナー」で同じ条件を入力し、所得税・復興特別所得税・申告納税額が一致することを確認する（ケース表を `docs/verification/` に保存予定）。
- 自治体の住民税・国保の試算シミュレーターとの比較。
- 確認結果はルールの `notes` の `status` を `verified` に更新して記録する。

## 5. E2E 確認手順（現時点では手動）

1. `.env.local` を作らずに `npm run build && npm start`（デモモード）
2. `/home` → `/login` にリダイレクトされる
3. 「サンプルデータで試す」→ ホームに計算上の残額・税金の一覧・警告が表示される
4. メニュー →「デモを終了」→ ログイン画面
5. 「初期設定から試す」→ 9ステップを入力 → 確認画面で未入力項目が表示される → 保存 → ホーム
6. 売上を登録（10.21%で計算）→ 売上一覧の合計・未入金・源泉徴収が更新される
7. 経費を家事按分30%で登録 → 経費になる金額のプレビュー、注意点に「按分の根拠」が出る
8. 仕訳を手入力し、借方・貸方を不一致にして保存 → エラーが表示され、入力内容は残る → 一致させて保存
9. 固定資産を登録 → 帳簿の試算表が「貸借一致」、ホームの予測に減価償却費が反映される
10. 売上を編集して入金済みにする → 削除 → 合計が元に戻る
11. 存在しない ID の編集画面は 404
12. レシート画像を選んで読み取る → 確認画面（デモ表示）→ チェックなしで登録するとエラー（入力は残る）→ チェックして登録 → 経費一覧にレシートのアイコン
13. 同じ画像をもう一度読み取る → 重複の警告 → 登録しない → 削除
14. 未ログインで画像の URL を開くとログイン画面へリダイレクト
15. 控除・給与の入力で配偶者（年収130万円→所得56万円を反映）・扶養親族・生命保険料・ふるさと納税を入力 → 控除額の見込みが表示される → 保存 → 税金の内訳に控除・住民税の内訳が出る
16. 初期設定を保存し直しても控除の詳細が残る
17. 納付カレンダー: 取り置き額を入れると毎月の目安が下がる → 通知書（住民税の年税額）を入力すると4期に分かれて「確定」、ホームの住民税も確定額に → 各期の合計と年税額が違うとエラー → 納付済みにする
18. 自治体の設定で国保料率を入力 → ホームの国保料が再計算される
19. シミュレーション: 例のボタン（消耗品10万円・備品30万円・売上+50万円・青色65万円・共済）で結果と説明文が変わる。売上を減らした場合も正しい説明文になる
20. 年末予測の修正: 残りの売上を入力 → ホームの予測方法が「手入力」になる
21. スマートフォン幅（390px）で横スクロールが発生しない・表の数字が重ならないこと
