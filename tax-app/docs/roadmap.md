# 開発ロードマップ（roadmap.md）

各段階で動作確認・テストを行ってから次へ進む。最初からすべての機能を一括生成しない。

| 段階 | 内容 | 状態 |
|---|---|---|
| 第1段階 | プロジェクト基盤、ログイン、初期設定、基本画面 | ✅ 実装済み（本コミット） |
| 第2段階 | データベース、仕訳、帳簿、売上・経費登録 | ✅ 実装済み |
| 第3段階 | レシート撮影、OCR、仕訳候補、確認・修正 | ✅ 実装済み（実際の Claude API での読み取り精度は要検証） |
| 第4段階 | 年度別税務ルール、所得税計算、税額予測（本実装） | ✅ 実装済み（令和8年分の一部は公式資料での最終確認待ち） |
| 第5段階 | 翌年度の住民税・国保等の予測、納付時期別表示 | ✅ 実装済み（翌年度の国保軽減基準は未公表のため今年度の基準で試算） |
| 第6段階 | 収入・経費・控除のシミュレーション | ✅ 実装済み |
| 第7段階 | 決算書、確定申告書、PDF出力 | ✅ 実装済み（転記用の金額。正式な様式・e-Tax は未対応） |
| 第8段階 | テスト、セキュリティ確認、専門家レビュー、公開準備 | ✅ 開発側の作業は完了（専門家レビュー・国税庁資料の確認・API の接続は公開前に実施） |

参考（事業計画上の予定）：2026年10〜11月 基礎システム、12月 白色申告版、2027年1月 青色申告版、2〜3月 最終検証・改善。

## 外部 API の接続は最後に行う（方針）

レシート読み取りの AI（Claude API）などの外部 API は、システム全体を作り終えてから最後に接続・検証する。
それまでは、API キーがなくても動く状態（デモ用の仮データ・手入力）で開発を進める。

- [ ] `ANTHROPIC_API_KEY` を設定し、実際のレシートで読み取り精度を評価する（第8段階の前）
- [ ] 1枚あたりの費用と料金プランの採算を確認する
