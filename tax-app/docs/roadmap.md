# 開発ロードマップ（roadmap.md）

各段階で動作確認・テストを行ってから次へ進む。最初からすべての機能を一括生成しない。

| 段階 | 内容 | 状態 |
|---|---|---|
| 第1段階 | プロジェクト基盤、ログイン、初期設定、基本画面 | ✅ 実装済み（本コミット） |
| 第2段階 | データベース、仕訳、帳簿、売上・経費登録 | ✅ 実装済み |
| 第3段階 | レシート撮影、OCR、仕訳候補、確認・修正 | ✅ 実装済み（実際の Claude API での読み取り精度は要検証） |
| 第4段階 | 年度別税務ルール、所得税計算、税額予測（本実装） | 🟡 エンジンの土台のみ |
| 第5段階 | 翌年度の住民税・国保等の予測、納付時期別表示 | 🟡 簡易版のみ |
| 第6段階 | 収入・経費・控除のシミュレーション | ⏳ |
| 第7段階 | 決算書、確定申告書、PDF出力 | ⏳ |
| 第8段階 | テスト、セキュリティ確認、専門家レビュー、公開準備 | ⏳ |

参考（事業計画上の予定）：2026年10〜11月 基礎システム、12月 白色申告版、2027年1月 青色申告版、2〜3月 最終検証・改善。

### 第2段階で見送った事項（後続段階で対応）

| 事項 | 理由・予定 |
|---|---|
| 前年からの繰越（期首残高）・年次締め | 第7段階（決算書）で実装 |
| 締めた期間の修正禁止・逆仕訳 | 年次締めと合わせて第7段階 |
| 一括償却資産・少額減価償却資産の特例 | 適用条件と令和8年度改正の確認が必要。現在は画面で案内のみ |
| 定率法・中古資産の耐用年数 | 個人の法定償却方法は定額法のため後回し |
| 現金主義（小規模事業者の特例）・前受金 | 未対応。売上は発生主義で計上 |
| 消費税区分の集計 | 区分は記録済み。課税計算は第4段階以降 |
| 勘定科目の名前変更・無効化 | 既存仕訳への影響を整理してから対応 |
| デモモードの帳簿の永続化 | デモはサーバーのメモリ保存（再起動で消える）。本番は Supabase を使用 |

### 第3段階の確認事項・見送り

| 事項 | 内容 |
|---|---|
| 実際の読み取り精度 | この開発環境には API キーがないため、Claude API での実際の読み取りは未検証。実レシート20〜30枚程度で精度（日付・金額の正答率、null にすべき項目を推測していないか）を確認する評価セットを作る |
| 税率混在レシートの分割登録 | 10%・8%混在は主な税率を選ぶ方式。税率ごとの分割は消費税計算（第4段階以降）と合わせて対応 |
| HEIC 画像 | 端末が変換できない場合は非対応（カメラ設定の「互換性優先」を案内） |
| PDF の領収書 | 未対応 |
| 複数枚の一括撮影 | 未対応 |
| 電子帳簿保存法の要件（検索要件・タイムスタンプ等） | 要件の確認が必要。現在は画像とハッシュ・アップロード日時を保存 |
| 費用 | 読み取り1枚ごとに API 料金がかかる。料金プラン（月額500円案）との採算を確認する |

## 第4段階：所得税計算の本実装

1. 令和8年分の税務ルールを国税庁の公式資料で確認し `provisional` を外す
2. 配偶者控除・扶養控除・医療費控除・寄附金控除などの計算
3. 給与所得との合算（給与所得控除）
4. 国税庁「確定申告書等作成コーナー」の計算結果との照合テスト

## 第5段階：翌年度の負担

1. 自治体の国保料率入力画面（医療・支援・介護・子ども子育て支援金分）
2. 住民税の非課税判定・人的控除差額
3. 納付時期カレンダー、任意の取り置き額の設定
4. 予測・確定・納付済みの管理（通知書の金額を入力すると「確定」に）
