# 開発ロードマップ（roadmap.md）

各段階で動作確認・テストを行ってから次へ進む。最初からすべての機能を一括生成しない。

| 段階 | 内容 | 状態 |
|---|---|---|
| 第1段階 | プロジェクト基盤、ログイン、初期設定、基本画面 | ✅ 実装済み（本コミット） |
| 第2段階 | データベース、仕訳、帳簿、売上・経費登録 | ⏳ |
| 第3段階 | レシート撮影、OCR、仕訳候補、確認・修正 | ⏳ |
| 第4段階 | 年度別税務ルール、所得税計算、税額予測（本実装） | 🟡 エンジンの土台のみ |
| 第5段階 | 翌年度の住民税・国保等の予測、納付時期別表示 | 🟡 簡易版のみ |
| 第6段階 | 収入・経費・控除のシミュレーション | ⏳ |
| 第7段階 | 決算書、確定申告書、PDF出力 | ⏳ |
| 第8段階 | テスト、セキュリティ確認、専門家レビュー、公開準備 | ⏳ |

参考（事業計画上の予定）：2026年10〜11月 基礎システム、12月 白色申告版、2027年1月 青色申告版、2〜3月 最終検証・改善。

- [x] `tax-app/` に独立した Next.js 16 プロジェクトを作成（既存アプリに影響しない）
- [x] Supabase Auth によるログイン・新規登録・ログアウト、proxy による保護
- [x] デモモード（Supabase 未設定でも動作確認できる）
- [x] 第1段階のテーブルと RLS（利用者・事業者・年度別設定・控除・計算結果・操作履歴）
- [x] 初期設定（9ステップ、未入力の影響表示）
- [x] ホーム・税金ダッシュボード（納付時期別、計算上の残額、警告）
- [x] 税金計算エンジン（所得税・住民税・国保・事業税・消費税2割特例・年末予測）と単体テスト
- [x] 税金の内訳・税務ルールの確認状況画面
- [x] 設計書 7点

## 第2段階：取引・仕訳・帳簿

1. `accounts`（標準勘定科目の seed）、`transactions`、`journal_entries`、`journal_lines`、`fixed_assets` のマイグレーション
2. 仕訳の貸借一致検証（DB トリガー＋アプリ側）、修正履歴
3. 売上登録（発生日・入金日・源泉徴収）、経費登録（家事按分）
4. 仕訳帳・総勘定元帳・試算表・損益計算書
5. ホームの売上・経費を概算入力から取引集計に切り替え（概算入力は「開始残高」として扱うか検討）
6. 固定資産・減価償却（少額減価償却資産の特例などは公式資料を確認して実装）
7. 税務上の注意点（売上と入金の差異、重複、家事按分の根拠不足）

## 第3段階：レシート・OCR

1. Storage 非公開バケット・ポリシー
2. 撮影・アップロード（スマートフォンのカメラ起動、画像圧縮）
3. AI・OCR 連携（サーバー側のみ）。読み取れない項目は未確認として表示
4. 確認・修正画面 → 取引・仕訳の作成、証憑との関連付け
5. 重複登録の警告

## 第4段階：所得税計算の本実装

1. 令和8年分の税務ルールを国税庁の公式資料で確認し `provisional` を外す
2. 配偶者控除・扶養控除・医療費控除・寄附金控除などの計算
3. 給与所得との合算（給与所得控除）
4. 国税庁「確定申告書等作成コーナー」の計算結果との照合テスト

## 第5段階：翌年度の負担

1. 自治体の国保料率入力画面（医療・支援・介護・子ども子育て支援金分）
2. 住民税の非課税判定・人的控除差額
3. 納付時期カレンダー、任意の取り置き額の設定
4. 予測・確定・納付済みの管理（通知書の金額を入力すると「確定」に）

## 第6段階：シミュレーション
（`screens.md` の設計メモを参照）

## 第7段階：決算書・申告書・PDF

1. 年次締め処理
2. 収支内訳書（白色）→ 青色申告決算書 → 確定申告書（第一表・第二表）
3. 入力不足・計算矛盾の検出、対象外ケースの明示
4. PDF 出力、作成履歴
5. e-Tax の仕様・データ形式・本人確認・電子署名を調査（提出機能は別途）

## 第8段階：公開準備

テスト拡充、セキュリティレビュー、税理士等の専門家レビュー、利用規約・プライバシーポリシー、バックアップ方針、課金。
